# 道具、Excel与交付

## 道具

- 以剧本和核对后的表为依据，不凭空增加故事道具。纯白背景、主体完整、边缘清晰，画幅适应物体，不全裁成正方形。
- 除非原文明示旧、损坏或磨损，默认全新。包与手表在原文无指定时可做豪华且有设计感版本；借鉴工艺、比例和材质，默认原创标识，不把虚构品牌写成原文事实。
- 独立道具生图默认排除床、椅子、门等空间构件；这不意味着场景图移除这些家具。用户明确列入时按本次要求处理。
- 文件、合同、证书、短信文字按原文语言、姓名、日期、金额和句意准确呈现，排版清晰美观、符合国家年代。未提供的全文不能伪称原文；使用已知文字，必要补全标为美术拟稿。
- 文件文字逐项放大核对。图像工具无法准确呈现时，用可控排版制作文字层并用允许的工具合成，或标明文字未通过；乱码图不能合格交付。

## Excel图片

先检查工作表、表头、原编号与既有嵌图。按“编号→图片文件”匹配，不能按文件排序猜对应。一编号多图新增变体列或变体行，保留原编号，不覆盖其他信息。

真正嵌入图片，不只填本机路径。等比缩放、留边距；调整图片列宽与行高，编号、名称、文字仍便于查看。按需冻结表头编号列、设筛选换行。保留原工作表、公式、格式和已有图片；工具有限制时另存新文件再查兼容性。

保存后重新打开或渲染，抽查首、中、尾及多图行；不遮文字、不串行、不拉伸。核对清单、嵌图数量和既有图片。数量一致不代替对应关系与视觉检查。

## 清单与脚本

UTF-8 JSON；`assets` 数组每项含 `image_id`（唯一图片编号）、`source_id`（原编号）、`category`、`source`（原文位置或证据）、`image_path`、`prompt_path`、`status`。路径相对清单目录，待生成可为空。状态：pending/generated/needs_revision/checked/user_approved/excluded/failed。最终两种状态还须填 `review` 写实际检查结果。

```sh
python3 scripts/asset_manifest.py init ./项目目录
python3 scripts/asset_manifest.py audit ./项目目录/manifest.json
python3 scripts/asset_manifest.py package ./项目目录/manifest.json ./交付.zip
```

脚本仅用标准库。audit 检查编号、来源、路径、PNG/JPEG头部尺寸和提示词、状态。package 要求所有非排除项已人工检查且文件存在，再收录图片、提示词、清单/CSV；有待处理项就停止。脚本不验证审美、不完整解码图片、不检查Excel，需用对应工具另做。

## 交付

逐张看最终图；用可用图片库完整解码；清单每个有效编号有选定版本、来源及提示词；检查表格嵌图与原表保留；测试ZIP可打开、数量一致。交付图片原文件、带图片Excel（若要求）、提示词索引、项目记录和ZIP。公开技能不包含用户剧本或素材。

报告实际生成、已检查、用户认可、排除、失败和待核数量；缺项说明原因。不得把派发、工具返回成功或创建文件名说成图片已交付，不承诺没执行的逐图检查和质量比较。
